## Two immutable levels, no circular identity claims

`buildFcfMissingInventoryPlan({sourceCommit,seedEvidence,policyHashes,now})` produces the fixed parent with exact ordered children/fetch IDs/reuse descriptors and canonical sorted-key SHA excluding its own hash field. Top-level fields are exactly `schemaVersion,kind,preset,sourceCommit,createdUTC,maximumSourceGETs,stopOnDefect,seedBinding,policyHashes,limits,children,planSha256`; kind is `fcf-missing-inventory-plan`, maximumSourceGETs477 and stopOnDefecttrue. Children contain `targetSlug,competitionId,sourceCode,season,fetchIds,reuse,maximumSourceGETs`; reuse entries bind ID/raw SHA/length/original receipt and source capture commit. No preexisting source header/round/hash is invented for fetch IDs. Each child plan SHA is the same canonical hash algorithm over that child's exact fields plus the parent plan SHA.

Root reviews exact plan text/SHA after seed authentication and after the implementation/main commit is known. Dispatch requires main and this expected SHA, never arbitrary URLs, ID lists, budgets or policy JSON. Plan age is at most24h at first GET. The capture is limited to a45-minute source window from the first native GET, shared across children; no attempt begins unless its90-second timeout plus a15-second retention margin fits. Each job has a360-minute wall limit, coordination at most300minutes; timeout/expired window produces a failed diagnostic, not a larger allowance.

A plan cannot know the ID/digest of its future output artifact. The sealed parent completion receipt therefore binds actual child artifact IDs, ZIP digests, content manifest SHAs, job IDs, run/attempt/main commit and child-plan SHAs obtained from authenticated GitHub metadata after upload. The independent reader also receives those expected identities from root's authenticated transport; a self-reported artifact ID or `verified:true` is insufficient. Root's expected parent run/attempt/commit binds the dispatch. Manifest text is immutable after sealing. Never modify a first child to add a later failure.

## Capture contract: retain first, validate headers, stop on discovery

The single native request boundary accepts only the next exact URL `https://www.fcf.cat/ca/competicio/acta/<id>` with GET, `redirect:'manual'`, honest existing `SLFF fantasy (slff.eu; splih.94@gmail.com)` User-Agent,90-second whole-attempt timeout and no retries. Do not call `fcfFetch`, whose normal empty-body retry is inappropriate here, or a retrying helper. Count and durably append the attempt before invoking native fetch; an indeterminate failure still consumes that slot. Finite `SLFF_PREMOR_FAKTOR>=1`; no second attempt until at least3000ms×factor after completion/cancellation of the preceding one. Apply this across the child boundary, and pause before the first request following ES coordinator clearance.

For each response first retain original HTTP-decoded entity bytes without text reencoding, raw SHA/length, actual request start, response-header time and body-completion time. Preserve original bounded response bytes even when subsequent decoding/header validation fails. Receipt fields: `sequence,id,targetSlug,sourceUrl,method,startedUTC,headersUTC,capturedUTC,httpStatus,responseURL,redirected,responseHeaders,bodyState,bytes,rawSha256,artifactFile,validation`; `responseHeaders` is the existing bounded allowlist of content-type/encoding/length/date/last-modified, never cookies/auth tokens. Date/Last-Modified are server metadata, not capture timestamps. `capturedUTC` is null if a body did not complete; no average or batch timestamp can stand in for an individual receipt. Zero body is an accurately recorded empty response, never successful evidence.

On401/403/429 or redirect: permanently latch stop before reading/canceling, retain status/headers/receipt, and permit only a bounded best-effort body drain within the remaining attempt deadline for diagnostics. Cancellation/drain errors cannot remove the latch or start another request. For oversized/stream-failed bodies retain at most2MiB prefix with `bodyState:'truncated'`, separate prefix byte count/SHA and no full-body rawSha256; a partial body cannot enter a successful inventory. Challenge/unknown/invalidUTF8/BOM/wrong-page/empty/error bodies within the bound are retained before validation and stop globally. No redirect, alternate URL, proxy, challenge workaround, repeat-empty retry,5xx retry or later-child request follows any failure.

Before the next GET, validate strict UTF8/noBOM, ordinary acta page/nochallenge, exactly one unambiguous embedded actual acta route equal to requested ID,2026/27 season, exact competition/group, actual header round1–30, real current-season date, coherent known match status/score, and both exact header-side native club/category links and names. Use actual FCF RSC/header primitives. Reject absent/conflicting wrappers/routes/side links, self-fixtures, conflicting names for the same native identity, a17th club, duplicate directed pair or repeated club within an actual round, and a ninth fixture in a round as soon as observed. Markers are validated first from originals with the exact historical classifier and their actual rounds; online checks include them. Names/IDs may not be guessed from logos, player blocks, normalized aliases, numeric position or other fixtures. Header/schema drift stops the parent; preserve bytes for offline diagnosis.

The capture deliberately does not run normal individual-statistics parsers or generate player/appearance/goal canonicals. A status/result inconsistency already visible in the header is a discovered defect and stops. If any component or operator observes another new defect while capture is live, set the same global stop latch; ignoring a known defect because the stage is called inventory is forbidden. Hidden individual defects cannot be excluded by header validation and must not be advertised as checked.

## Sealing, child independence and offline audit boundary

Each complete child must close exactly240 IDs,30 actual rounds with eight fixtures/all16 native club-category identities per round,240 distinct directed pairings and stable native names. Header-calendar closure does not prove goalkeeper/statistics coverage. Header names preserve actual source spelling; no alias or normalizer may hide a conflicting native identity. Seal a child manifest only after all normal bodies/receipts and target original markers pass header closure. Its status is `inventory-complete`, `statisticsAudit:'not-run'`; no field may claim `ready`, `statisticsComplete` or keeper coverage. Successful inventory ZIP contains exactly `manifest.json` and240`acta-<id>.html` members. Manifest binds parent/child plan SHAs, execution identity, exact target/policy/seed binding, all240 descriptors, ordered native attempts and original/recent receipt distinction. No derived staff/individual rows or caller canonical objects appear.

G1 seals/uploads before the separate offline statistics audit. That audit reopens authenticated sealed bytes, independently rederives every header/receipt and runs unchanged strict ordinary document/keeper proof plus exact historical classification and full current calendar proof. No HTTP, DB connection or fallback is available to the audit. Write a separate `fcf-missing-inventory-offline-audit` schema1 result binding inventory artifact ID/digest/manifestSHA, audit commit/time and policy hashes. Capture's manifest remains immutable. Any normal warning, result/goals discrepancy, registration ambiguity, minute error, incomplete XI or noncontinuous exactly-one officialGK0–90 fails; the audit must not manufacture a role or exception.

G9 may begin only after successful G1 inventory upload AND successful offline strict audit, before the shared source-window deadline and without a stop latch. This is a source-continuation gate, not a DB readiness or release claim. G9 then follows the same sealing/audit sequence. A later G9 failure preserves the already sealed G1 artifact and its separately authenticated offline audit. It does not convert a partial G9 into evidence or invalidate G1 by requiring the whole parent run to succeed. If G1 audit fails, keep its complete inventory as diagnostic evidence and issue no G9 GET. A later independent reader can still inspect it, but no target source proof is emitted.

Failed child artifacts contain the manifest, all retained full bodies/prefixes and honest not-attempted descriptors for the remainder. Use `failed` status and fixed sanitized reason/first-defect ID. They never satisfy complete-child readers. If output safety/retention is indeterminate, return no `evidence_ready`; preserve local bytes without authorizing upload. No successful artifact is synthesized from partial files.

## Retention and authenticated replay

Per child:2MiB per source body/prefix,8MiB manifest,192MiB total expanded and100MiB actual ZIP. No symlinks/nonregular/unsafe ancestors/preexisting output, path traversal, duplicate members, race-changed files, BOM/invalid JSON or unknown manifest properties. Before each GET reserve2MiB plus remaining bounded manifest/ZIP-overhead space in both limits; maintain exact compressed-member sizes as members seal, rather than assuming compression or raw-size averages. If the next worst-case body cannot fit, stop before requesting. Keep only one live body buffer; source bytes go into invocation-owned exclusive files with durable receipts. Rehash every member before sealing. Upload failure stops later source work. No raw HTML goes in logs or committed fixtures.

Authenticated reader interface is `readFcfMissingInventoryArtifact({targetSlug,zipBytes,artifact,run,jobs,expected,plan,now}) -> MissingInventoryProof`. It validates actual ZIP SHA/size before bounded extraction; fixed member set, every original byte/receipt, complete closed schema, actual source attempts with exact order/count and timestamps, seed binding and independently derived header/calendar closure. It returns inventory-only proof tagged with its protocol. `expected` includes root-supplied parent planSHA, child planSHA, runId, runAttempt, sourceCommit, jobId, artifactId, digest, manifestSHA and seed identities. Reject expired/rehashed/partial/wrong-step/wrong-commit/wrong-attempt/foreign-group evidence. Inputs cannot supply canonical headers/statistics as proof.

Separate `auditFcfMissingInventoryOffline({inventoryProof,policyHashes,now}) -> OfflineInventoryAudit` reparses original bytes with unchanged strict normal parsers, classifies exact marker originals and performs full keeper/calendar validation. `readFcfMissingInventoryAuditArtifact({zipBytes,artifact,run,jobs,expected,inventoryProof,now}) -> AuditedInventoryProof` authenticates/rebuilds that separate audit. Neither reader accepts success booleans as authentication.

A final `composeFcfCapturedTargetEvidence({inventoryProof,auditProof,targetSlug,now}) -> TargetEvidence` is the only bridge into the reviewed v2 target packet. It requires both authentic proofs for exactly the same child/hash, carries actual fresh individual receipts or exact marker-original provenance unchanged, and reruns ordinary age/pending/prelaunchR6 rules at composition time. No artificial cache key, cache mtime, `retained-cache` lineage or final-audit identity is created. Existing target-evidence/packet integration needs an explicit new inventory input branch, with cross-protocol rejection tests; never disguise this artifact as a cache export or expand a reader to accept arbitrary lineage.

Target release still requires the separate all-four cleanup originals/before-image/applied receipt and fresh read-only DB inventory plus locked DB readiness/price/legal15/deadline checks. A target's pending known-imported ID remains a failure. Capture cannot manufacture DB imported IDs; the later authenticated DB inventory owns that comparison. If another source refresh becomes necessary due to age or schedule drift, this design supplies zero extra GET authority.

## Implementation/review boundary and risks

This proposal authorizes no implementation or source dispatch by itself. Root owns fresh builder review, source-budget review, exact-main code/CI review, actual seed staging, and the later explicit execution decision. The accompanying plan is bounded to this new source-inventory protocol, its pure offline audit/reader/bridge, coordinator integration and tests. It contains no cleanup execution, migration180400, normal import, prices, position changes, activation, email or other-country modifications.

Load-bearing risks: original seed transport is not yet available; parent budget cannot be compiled without it. Header-only acquisition cannot exclude hidden normal statistics defects; mandatory offline audit may hold after spending a child budget. Bounds may terminate before240 if actual bodies compress poorly; never expand them. Forty-five minutes may expire under slow responses or inter-job scheduling; no time/budget refresh. Native name/category/calendar drift can cause an early hold. Source capture can age before future readiness; no timestamp replacement. Cross-run artifact hashes and a failed-parent/successful-child exception require independent authentication tests. Already-running old coordinators can overlap unless root waits for them before dispatch. None of these permits inferred bytes, invented lineage or broader approval.
