# Baden R10 current-only foundations

This change is deliberately nonoperational. It supplies reusable scope and accounting primitives for the next implementation. It exposes no capture command, workflow, dispatch or admission capability. It creates no new CURRENT execution or read-result proof. The existing fixed-pair producer/readers and native catalog remain unchanged.

`scripts/fussball-baden-r10-foundation.mjs` exports:

- `fussballBadenR10FoundationDescriptor()`: the intended fixed Baden `03188V27L800000JVS5489BTVU7GTVLE-G`, season `2026/27`, all reports (`reportLimit: null`), `community-v1`, current reservation 780, archive reservation 0, total cap 5000. Its R7 archive reference is explicitly an unvalidated locator.
- `inspectBadenR10AttemptJournals(files)`: pure inspection of retained intent/outcome byte buffers. Failed outcomes remain charged. An unsettled intent remains charged and makes exact accounting unknown. Missing, empty, malformed, truncated, invalid UTF8, duplicate or incompatible journals never establish zero expenditure. The output is DATA and cannot authorize a capture.
- `readFussballBadenR10AccountingFoundation({github})`: a private historical accounting capability. It reuses the existing authenticated R7/R8 historical-budget reader; authenticates the pinned actual R9 run, complete jobs, complete artifact inventory and immutable ZIP digest; validates the exact outer/current manifest pins, intent/outcome hashes and snapshot; and repeats mutable hosted metadata before issuing the capability. The adapter receives fixed own-repository GET paths only. Errors do not expose adapter error bodies.
- `getFussballBadenR10AccountingFoundation(proof)`: defensive copies of accounting, certificates, original R9 ZIP/accounting leaves and historical budget files. Copied or serialized capabilities are rejected.

R9 authenticates 587 requests: 584 successes and 3 failures. Together with the existing 3020 historical receipt this proves an **authenticated minimum of 3607**, not a fresh cumulative total. The result therefore has `freshAccountingKnown: false` and `freshCumulativeRequests: null`. R9's original current clock remains `2026-10-29T10:43:41.514Z`, expiring `2026-10-30T10:43:41.514Z`; historical accounting remains readable after that expiry and grants no current authority. No full R7 archive-original ZIP is fetched by this foundation. The existing R7 attestation is fetched only for the historical budget proof.

It makes no network or provider GETs and does not invent R10 handles. It tests failed/pending accounting, absent artifacts, malformed journals, pin mismatches, expiry, late metadata drift, defensive copies and the absence of an archive-original GET.

```sh
FUSSBALL_R10_FOUNDATION_EVIDENCE=/absolute/path/to/2026-10-26-german-unlock-screen \
  node --test scripts/test-fussball-baden-r10-foundation.mjs
```

No deployment, activation, current-source freshness or production readiness is established by these tests.
